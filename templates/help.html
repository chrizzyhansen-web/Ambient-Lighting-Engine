Setup and how it works

Choose the quick setup guide or the delightfully nerdy details.

This app reads the current Spotify track and asks Groq to make one full-song lighting plan from its title, artist, and album art. The lights follow that palette with flowing color movement. It does not listen to the audio.

What you need first

1. Spotify desktop and Spicetify (recommended)

The Spicetify bridge reads the track from the Spotify desktop app and works with a free Spotify account. Spotify must be installed and opened once before installing Spicetify. The alternative Spotify Developer API requires the app owner's Premium account under Spotify's current Development Mode rules.

2. Python 3 on Windows

Install Python 3 and enable “Add Python to PATH.” The setup batch file installs the app's Python packages for you.

3. A Groq API key

Get a key at console.groq.com/keys. Groq sees track metadata and a small, compressed album image, not the song audio.

4. A Govee API key and device details

The key is used for cloud backup and to read the device's capabilities. You also need the device ID and model/SKU from Govee Home. Turn on LAN Control in the light's settings for the smoothest animation.

Steps to get going

Step 1 — Open the app

On Windows, double-click Setup (run once).bat to install dependencies. Then run Start App.bat whenever you use the app; keep its window open. It opens the local setup page in your browser.

Step 2 — Install Spicetify

Follow the install instructions at spicetify.app. Fully close Spotify while applying Spicetify changes. The app's Spotify Web API option is an alternative, but needs a Spotify developer app and OAuth setup.

Step 3 — Add your Groq and Govee details

Paste the Groq API key, Govee API key, device ID, and model/SKU into Setup, then save. Find the Govee key in Govee Home under Profile → Settings → Apply for API Key; the device ID and SKU are in the device details. Keep LAN Control enabled for local streaming. If you chose Spotify Web API instead of Spicetify, connect your developer app from the Spotify section.

Step 4 — Install the bridge extension

On the Setup page, click Install extension automatically. It writes the extension with your local bridge token and applies it. If Spicetify reports outdated Spotify files, the installer attempts its restore/apply recovery and shows the command log if it still fails.

Step 5 — Check the Spotify connection

Open Spotify desktop and play a song. The Setup page should show a green Spicetify bridge dot within a few seconds. If you use the Web API option, finish its Connect Spotify sign-in instead.

Step 6 — Start the engine

Open Dashboard and press Start engine. Play Spotify. The page shows the current song, connection transport, and live lighting preview.

Dashboard controls and playback states

Brightness

Enter a maximum brightness from 1–100%. The default is 5%; this is a hard device brightness ceiling, even when the colors brighten during a song.

Neon segment flicker

When local streaming is available, a few neighboring segments sputter brighter and dimmer like a failing neon sign. Bursts stay under three seconds and happen more often with song energy. Disable it for steady color.

Paused playback and errors

Paused playback gets slow blue water-like color drift with flicker off. Playback or AI errors show steady amber. The sleep timer turns the lights off only when its timer expires.

Saved song plans

Plans created for songs you play are compressed locally. Delete one to have Groq regenerate it next time. The older 84-plan archive is kept separately: its exact songs still use their archived plans, and the plans also guide new songs.

Poll interval and sleep timer

Poll interval controls how often the app checks Spotify; it does not make extra Groq requests. Set the sleep timer to 0 to leave it off, or enter a number of minutes before the app turns the light off.

If something's not working

Check the Setup bridge dot first. If it is disconnected, open Spotify desktop, confirm the extension is enabled, and try the automatic installer again with Spotify fully closed. For a Groq 401, replace the API key. If the dashboard says Cloud API backup, local LAN streaming is unavailable; enable LAN Control and check that the computer and light share a network. Re-copy any key that may have extra spaces.

Architecture overview

webapp.py (Flask) serves the setup wizard and dashboard. By default it reads now-playing data from spicetify_bridge.py (pushed from the Spotify desktop client); it can optionally use Spotify's OAuth Web API instead if you pick that in Setup. engine.py runs the poll loop in a background daemon thread, started/stopped via /engine/start and /engine/stop. State (current track, last lighting decision, errors, sleep-timer countdown) is exposed via /api/status and polled client-side every 2s. All credentials persist in config.json (gitignored) rather than a .env file.

1. Spicetify bridge (default track source)

Why not the Spotify Web API by default

The Spicetify path reads the desktop player's state locally, so it avoids OAuth and Spotify Web API access requirements. Choose the Spotify API option only if you have already configured a developer app and its OAuth credentials.

How it works

spicetify-extension/ambientLightingBridge.js runs inside the Spotify desktop client once loaded via Spicetify. It listens to Spicetify.Player's songchange, onprogress, and onplaypause events, reads metadata and playback progress, and POSTs to http://127.0.0.1:5000/api/spicetify/now-playing at most once per second, plus immediately on song change and play/pause.

Album art URL conversion

Spicetify's metadata.image_xlarge_url field is an internal URI (spotify:image:<hash>), not a fetchable URL. The extension converts it to https://i.scdn.co/image/<hash> before sending, since that's what ai_lighting_engine.py needs to download the artwork bytes.

Server side

spicetify_bridge.py holds the latest pushed state in memory (thread-safe) and exposes get_now_playing() with the exact same return shape as SpotifyClient.get_now_playing(), so engine.py swaps between the two sources based on cfg["track_source"] with no other code changes. State is considered stale (and playback treated as "nothing playing") if no push has arrived in STALE_AFTER_SECONDS (15s) — this is what powers the connected/disconnected dot on the Setup page.

Bridge token

A random 32-char hex token (bridge_token in config.json, generated on first run via secrets.token_hex(16)) is required on every /api/spicetify/now-playing POST via the X-Bridge-Token header. This isn't about internet security (the endpoint only binds to 127.0.0.1) — it's so the Setup page can tell "nothing is reaching us" apart from "something's reaching us with a stale/wrong token" (the unauthorized_recently flag), which is a much faster thing to debug than a plain silent timeout.

Update cadence

The extension pushes progress at most once per second and sends immediate updates for song changes and play/pause. The engine checks the local bridge every 0.3 seconds. The Spotify Web API mode uses the dashboard poll interval; its queue endpoint is checked about every 20 seconds.

One-click installer

/api/spicetify/install finds the Spicetify config path, writes the extension with your bridge token, enables it, and applies the configuration. It captures the command output for troubleshooting and attempts spicetify restore backup apply if Spotify's preprocessed files are outdated. Fully close Spotify before applying changes. Manual installs need the token from Setup in the extension's BRIDGE_TOKEN constant.

2. Spotify Web API (alternate track source)

Spotify currently requires the app owner to have Premium for Development Mode apps. See Spotify's quota mode requirements.

Create the app

developer.spotify.com/dashboard → Create app. Add http://127.0.0.1:5000/spotify/callback as a Redirect URI — must match exactly, including the port. Copy the Client ID and Client Secret into the setup form. Development Mode currently requires Premium on the app owner's account, even though the Spicetify bridge does not.

OAuth scopes used

user-read-currently-playing and user-read-playback-state.

Token lifecycle

Access tokens expire after ~3600s; SpotifyClient refreshes 60s early automatically. Spotify occasionally rotates the refresh token itself on refresh — the client captures and swaps it in-memory.

3. AI lighting with Groq

Groq

Get an API key from console.groq.com/keys. For a new track, the app sends title, artist, and the cover resized to at most 128×128 pixels and recompressed as a quality-45 JPEG. The image is attached once on the first request; retries omit it. Groq returns the original full-song plan: six timed color keyframes plus palette anchors. Groq does not receive or hear the audio.

Plan cache, archived references, and preloading

New plans are stored in compressed song_lighting_cache.json.gz, keyed by Spotify track ID, then sampled locally throughout replays. The separate track_plans.json.gz archive holds 84 old-format plans: a matching Spotify ID reuses its exact archived plan, while new songs can receive up to three examples chosen by title/artist word overlap with the examples' descriptions. That matching is a heuristic; it is prompt guidance, not model fine-tuning. Spotify's next queued track is preloaded when available. Groq requests are serialized and locally limited to two per rolling minute.

Paused playback and errors

Pause uses a low-energy blue palette with no transient effects, so neon flicker stays off. LAN control renders its water drift at up to 30 FPS; cloud fallback makes a gentle whole-light color change about every 2.5 seconds. Playback or AI errors still show steady amber. A Groq 401 indicates an invalid, expired, or revoked key.

Pausing playback during the first decision

The Spicetify bridge includes the next queued track when Spotify exposes it, letting the engine generate and cache that plan while the current song plays. If a new track has no ready plan yet, the lights hold their previous state while Groq works; the engine no longer cycles a white loading pattern across the strip.

4. Govee API setup

Local control first, cloud backup

The app discovers your light on the local network and sends commands over UDP. Enable LAN Control in Govee Home and put the computer and light on the same network. If discovery fails or a LAN send raises an error, the app falls back to Govee Cloud API. UDP has no acknowledgement, so a command silently ignored by the device cannot trigger fallback.

Keep a Govee API key for backup

Govee Home app → Profile → Settings → Apply for API Key (usually near-instant via email).

Find your device + SKU

The exact device (MAC-style ID) and sku (e.g. H619B) are needed for setup. At startup the app uses the API key for a read-only capability lookup; normal control commands go over LAN whenever discovery succeeds.

Rate limits

Cloud API control is only the fallback and is throttled to a 0.5-second minimum between calls. Local Razer/DreamView frames are paced at up to 30 FPS using a reused UDP socket; this is local streaming, not a series of cloud calls.

Segmented (RGBIC) control caveat

The startup capability lookup checks whether this exact Govee device advertises segmentedColorRgb and reads its zone count. Compatible devices receive per-zone Razer/DreamView frames over LAN. The flowing palette renderer also carries a white wave across the strip on song changes and large palette shifts. Cloud-only control updates much less often to respect rate limits; its song-change fallback is a brief white cue, not a streamed wave. Devices without independent zones use whole-light color.

5. Animation, flicker, and color safety

Water-like motion

effects.py renders the palette locally with layered, non-synchronized waves and Oklab color math. Track energy changes the wave speed and spread. LAN can stream up to 30 frames per second; the cloud API cannot stream fluid animation.

Neon flicker

The optional effect chooses a short contiguous group of one to three segments, then gives each a deterministic but irregular sequence of bright and dim holds. Bursts are 0.8–2.4 seconds, capped below three seconds, and recur sooner at higher energy. Pause sends no flicker events.

Brightness and near-black protection

The dashboard brightness value is a hard device-level maximum, default 5%. The renderer keeps its lightness above the normal ambient floor and raises near-black animation colors proportionally so their strongest RGB channel is at least 128, including after frame smoothing. This protects against animation frames that look off; the sleep timer still intentionally powers down the light when it expires.

Running it manually (without the web UI)

If you'd rather script it directly: instantiate SpotifyClient, GoveeClient, and GroqLightingEngine yourself (see engine.py for the exact call pattern) and drive your own loop — no Flask required. Useful for running on a headless device like a Raspberry Pi as a systemd service instead of a browser-controlled app.

Sleep timer implementation detail

During the final 15 minutes, the sampled song decision is overridden with a deep-blue color and a longer update interval; no extra Groq request is made. When the timer reaches zero, the engine calls govee.set_power(False) and exits. A zero-minute timer means the timer is off.
